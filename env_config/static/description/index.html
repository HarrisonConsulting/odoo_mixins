ENV-first configuration.

Inherit env.config.mixin to read configuration from environment variables with ir.config_parameter fallback. Supports explicit ENV var mapping and typed accessors for secure, production-ready config management.

See how it works Talk to us →

Why

Credentials and secrets should never live in database records. The standard pattern is environment variables — secure, auditable, and easy to rotate. But Odoo operators often prefer database configuration for convenience. This mixin bridges both: check ENV first, fall back to database settings.

How it works

  1. Inherit the mixin
    Your model inherits from env.config.mixin and declares _env_config_map with explicit ENV var names.
  2. Lookup order: ENV > database
    Call _get_config('key'). Mixin checks environment variable first; if missing, reads from ir.config_parameter.
  3. Custom ENV var names
    Map keys to ENV var names. Example: _env_config_map = {'api.key': 'MY_SERVICE_API_KEY'}. Falls back to auto-conversion: api.key → API_KEY.
  4. Typed accessors
    Get strings, integers, floats, and booleans with type coercion. Defaults to string if type is not specified.

What's in the box

ENV-first lookup

Environment variables take priority. Secrets stay out of the database in production while keeping database settings available for development.

Custom ENV mapping

Explicit _env_config_map maps config keys to environment variable names for standard services.

Type coercion

Parse environment variables as strings, integers, floats, or booleans. Sensible defaults for missing or unparseable values.

Compatibility

Odoo 19.0

Depends on base only. No external Python dependencies.

Field note — ENV takes priority

Always check environment variables first before falling back to database config. This ensures production secrets are never exposed in database records if a backup is leaked.
